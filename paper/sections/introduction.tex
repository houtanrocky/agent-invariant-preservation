\section{Introduction}
Repository-level software engineering requires changes that remain consistent with behavior beyond
the edited function. Benchmarks such as SWE-bench evaluate issue resolution in existing projects
\cite{swe-bench}, and SWE-agent studies interfaces for agent interaction with code and tools
\cite{swe-agent}. For stateful backends, a change may additionally need to preserve requirements
over balances, ownership, retries and concurrent histories. These are motivating concerns, not
observed failures in the intended subject.

We plan to examine feature correctness jointly with preservation of pre-existing transactional
invariants. The intervention will make already-available requirements salient through structured
guidance; it will not supply otherwise unavailable correctness information. Intended contributions
are a bounded validated task collection, an auditable comparison and a trace-grounded failure analysis.
The novelty of this framing remains subject to a fuller review of closely related work.
